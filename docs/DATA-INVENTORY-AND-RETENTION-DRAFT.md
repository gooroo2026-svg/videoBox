# VideoBox data inventory and retention decisions (draft)

**Reviewed against source:** 14 October 2026  
**Operator:** Nigeria  
**Audience:** adult-only phase one (18+ self-attestation; not verified age assurance)  
**Status:** source-code inventory, not a complete provider audit or legal determination. Retention and deletion periods remain owner/legal decisions.

This inventory reflects the app code and SQL files inspected in this project. It does not prove what is deployed in Supabase, which logs/backups are enabled, what subprocessors retain, or what the production host records. Confirm each row against live settings before publication.

## Owner decisions and legal review required

1. Choose a defensible retention schedule for every row above, with different periods where needed for user content, support reports, copyright records, fraud/security, and accounting.
2. Confirm the actual Supabase project region, Next.js host, email provider, subprocessors, analytics/ad providers, logs, backups, and data flow. Record locations and applicable transfer safeguards.
3. Name a monitored privacy contact and define request authentication, response deadlines by country, deletion exceptions, appeal/complaint route, and backup expiry. The app does not yet provide a complete account/data deletion process.
4. Have Nigerian counsel/DPCO assess NDPC category/registration, cross-border transfers, breach response, retention, age approach, and whether a DPIA/DPO is required. Have qualified local counsel assess each additional enabled market.
5. Reconcile the published Privacy Notice with the verified production inventory immediately before release and after each provider/feature change.

Do not copy a guessed retention number into the public Privacy Notice. The owner and qualified counsel must approve the actual schedule.
